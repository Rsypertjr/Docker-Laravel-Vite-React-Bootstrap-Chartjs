
> # ***[Vote Parsing Application](https://preselections.rsypertjr.net/)***
>- This app parses available voting data of the 2020 Presidential election.  It use a Laravel backend that includes an API for using ***[Atlas Cloud MongoDB](https://account.mongodb.com/account/login?signedOut=true)*** for storing ***Parsed-Voting-Data*** after initial retrieval of raw voting data.  The
>***Parsed-Voting-Data*** is available for future access and retrieval thru API for analytical processing in the App.
>- The App presents a ***Votes-Table*** and different ***Analytical Charts and Features***.  The charts are arrived at using ***[ChartJS](https://www.chartjs.org/)*** software package within React components.
>- This app also uses ***[Vite](https://vitejs.dev/)*** and ***[InertiaJS](https://inertiajs.com/)*** technologies work together to allow routing to ***[React]
>(https://react.dev/)*** Components through use of a PHP/Blade entry page and a React (.jsx) entry page



> ## Containerized Laravel Application using Docker and Docker-Compose
>- Using ***[Laravel 9](https://laravel.com/docs/9.x/installation)*** cloned into work directory by the command:
>   - ***git clone https://github.com/laravel/laravel.git***
>- docker/logs, docker/mysql, and docker/nginx folders are used to store respectively: 
>   - ***container logs***, 
>   - ***mysql data***, 
>   - and ***NGINX configuration files*** 
>   - to preserve data generated by the containers between restarts.
>- Uses Vite as a front-end asset bundler for integrating React inot Laravel
>- Uses InertiaJS to contain React and Laravel stack together and allow routing to React components
>- See **[Dockerize Laravel-Vite + React Application in Your Development Environment](https://betterprogramming.pub/
>dockerize-laravel-vite-react-application-in-your-development-environment-a118aea4a02d)** for greater details about this setup.


> ## **Docker Compose YAML File** 
>> ### ***[docker-compose.yml](https://github.com/Rsypertjr/Docker-Laravel-Vite-React-Bootstrap-Chartjs/blob/remote-docker-laravel-vite-votes/docker-compose.yml)*** 
>>> ### ***[This file](https://github.com/Rsypertjr/Docker-Laravel-Vite-React-Bootstrap-Chartjs/blob/remote-docker-laravel-vite-votes/docker-compose.yml)*** is used to configure the application services and create a network called ***'laravel'*** on which all the containers communicate. These Containers that run in the Dockerized network and operate as Services, are divided into:
>>> - ***Main container/services*** 
>>> - and ***Utility container/services***.
>
> - ***Main Containers*** run continuously and often restart on failure unless stopped
>   - **NGINX** the webserver which builds from the Docker file **docker/nginx.dockerfile**
>   - **PHP**  runs PHP-FPM process manager which builds from the Docker file **docker/php.dockerfile**
>   - **Mysql** is the database
>   - **Redis** can be used to store cache and sessions
>   - **Cron jobs** runs laravel cron jobs
>   - **Queues** runs laravel queues
>   - **Mailhog** provides local email testing.
>   - **phpMyAdmin** provides database management
>
> - ***Utility Containers*** run commands for customization and optimization of the whole application and get destroyed after running.
>   - **Migrate-Seed** runs migrations and seeders.  Should be run just after starting the main containers
>   - **Composer** runs composer commands.
>   - **Artisan** runs artisan commands.
>   - **Npm** runs npm commands.
> 
> - ***Container Techology Stack*** is the following:
>   - **Laravel v10.48.20 plugin v0.8.1** is in the **home directory**
>   - **php:8.2-fpm-alpine** in the **php.dockerfile** and the **php network container**
>   - **nginx:stable-alpine** in the **nginx.dockerfile** and the **NGINX network container**
>   - **mysql:8.0** in the **db network container**
>   - **Docker Version 27.2.0 build 3ab4256** is used within **Ubuntu 20.04**
>   - **docker-composer version 1.28.5 build c4eb3alf** is also used which eliminates the dash (-) in the docker-compose command:
>     - i.e. ***docker compose up --build nginx***


>
> ## Starting Docker Containers within Docker-compose network  -- ***(!For information but not for startup yet!)***
>> To start **All Containers** use command:
>> - **docker-compose up**
>
>> ## Main Containers
>> To start only the **Main Containers** and not the Utility Containers use command:
>> - **docker compose up --build nginx** 
>>   - It will ensure that only the containers that *nginx service depends on* will start. 
>>   - These are the containers listed in the ***depends_on*** section of ***nginx*** service.
>
>> ## Utility Containers/Services
>> **Utility Containers** are run using the command 
>> - **docker compose run --rm 'container_name'** 
>> - which removes a container after running it.

>## Artisan - Laravel application development CLI
>> ## **Artisan** is a command line interface that comes with Laravel that provides a variety of commands useful for application development **[See Artisan for more info](https://laravel.com/docs/11.x/artisan)**.
>
>## ***artisan container/service*** 
>> ### There is also an ***artisan container/service*** defined in ***[docker-compose.yml](https://github.com/Rsypertjr/Docker-Laravel-Vite-React-Bootstrap-Chartjs/blob/remote-docker-laravel-vite-votes/docker-compose.yml)*** which is useful for many things such as:
>   - **docker-compose run --rm artisan config:cache**
>     - resetting cache to current changes 
>   - **docker-compose run --rm artisan cache:clear**
>     - clearing cache
>   - **docker-compose run --rm artisan view:cache**
>     - resetting views files to current changes
>   - **docker-compose run --rm artisan view:clear**
>     - clearing current view files
>   - **docker-compose run --rm artisan config:clear**
>     - clearing currentconfigurations
>   - **docker-compose run --rm artisan config:cache**
>     - resetting to new configurations
>   - **docker-compose run --rm artisan route:clear**
>     - clearing set routes
>   - **docker-compose run --rm artisan route:cache**
>     - resetting to routes
>   - **docker-compose run --rm artisan route:list**
>     - clearing current routes
>   - **docker-compose run --rm artisan optimize**
>     - Creates a compiled file of commonly used classes in other to reduce the amount of files that must be included on each request
>     - also resets to new cache, configurations, and routes
>   - **docker-compose run --rm artisan serve**
>     - Helps running applications on the PHP development server.
>     - A combination of the prior commands is used ***i.e.(artisan config:cache,artisan route:cache, artisan view:cache)*** often to reset the app after changes before running ***php artisan serve***.  Also first using the corresponding ***:clear*** commands can be useful.
>     - Often ***php artisan optimize*** is sufficent for resetting an app.

> # **Setup Before Starting Containers** 
>>> ## Use ***composer service***, ***artisan service***, and ***npm service*** to set up ***'Vite'*** and ***'InertiaJS'*** software packages.
>>>>> ## ***'Vite'*** is a front-end asset bundler, and ***'InertialJS'*** allows React and Laravel stacks in one project such that both Laravel Views and React Components can be routed to.
>>>
>>>### ***docker-compose run --rm composer require inertiajs/inertia-laravel*** 
>>> - Installs InertiaJS
>>>### ***docker-compose run --rm artisan inertia: middleware***
>>> - Installs Inertia middleware
>>>### ***docker-compose run --rm composer require tightenco/ziggy*** 
>>> - The ziggy package allows front-end routes to be rendered with Javascript instead of PHP/Blade with the setup of a **Blade entry-point**  located at: *'/src/resources/views/app.blade.php'* for the Application UI
>>>### ***docker-compose run --rm npm i react react-dom @inertiajs/inertia @inertiajs/inertia-react jsconfig.json @inertiajs/progress***
>>> - To setup React, react-dom, and inertia front-end dependencies, including a progress bar. 
>>> - The routing of React Components is enabled by the ***[src/resources/js/app.jsx](https://github.com/Rsypertjr/Docker-Laravel-Vite-React-Bootstrap-Chartjs/blob/remote-docker-laravel-vite-votes/src/resources/js/app.jsx)*** entry file, and a Vite config file at: ***[src/vite.config.js](https://github.com/Rsypertjr/Docker-Laravel-Vite-React-Bootstrap-Chartjs/blob/remote-docker-laravel-vite-votes/src/vite.config.js)***.  
>>>### **docker-compose run --rm npm add @vitejs/plugin-react**
>>> - Installs Vite plugin for React
>>> - The same way a view can be routed to in Laravel with 'return('view')', now using 'return inertia('component')' routing goes to a React component, as seen in ***[web.php](https://github.com/Rsypertjr/Docker-Laravel-Vite-React-Bootstrap-Chartjs/blob/remote-docker-laravel-vite-votes/src/routes/web.php)***.

> # Starting the Containers
>## **Running migrations** to create database tables
> - ***docker-compose run --rm laravel-migrate-seed***
>
>## **Starting Main Containers** 
> - ***docker-compose up --build nginx***
>   - Run from project root
>
>## **Install PHP Packages**
> - ***docker-compose run --rm composer install***
>
>## **Install Javascript/React Packages**
> - ***docker-compose run --rm npm install***
>
>## **Configure Application**
> - Run the following commands to set the *application key* and *clear any cached config files*
>   - ***docker-compose run --rm artisan key:generate***
>   - ***docker-compose run --rm artisan optimize***

> # Running the React frontend
> Run React frontend in development mode with hot-reloading:
> - This is the format:
>   - ***docker-compose run --rm  --service-ports npm run dev***
> - Use as actual command:
>   - ***docker-compose run --rm --publish 5173:5173 npm run dev -- --host***
>   - ***--publish 5173:5173*** allows Browser to access at port published by NPM 
>   - ***-- --host*** exposes app to local area network
